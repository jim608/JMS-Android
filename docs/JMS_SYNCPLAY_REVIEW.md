# JMS .45 SyncPlay 審查（2026-10-24）

## 驗證方法與範圍

- 對照 `JMS_SYNCPLAY.md`、controller、transport、player、provider 與房間介面。
- 檢查房間建立、精確六位碼及碰撞、伺服器權限、播放／暫停／跳轉、Buffering／Ready、斷線恢復及登入世代隔離。
- 先保存現有測試結果，再以可重現的回歸案例驗證修正。
- 同步診斷只記錄本機時序、延遲及誤差；不記錄憑證、帳號、伺服器網址、影片名稱或房間識別。

自動化測試使用合成協定事件、可控時鐘與播放器替身；它們不能證明朋友網路、Android／Windows／Linux 跨裝置、實際轉碼或實體播放器的同步表現。本次不操作本人帳號、媒體、裝置，不發布 Release，不修改離線下載、評分或 Seerr。

## 初始檢查

文件已說明房間碼是可列出的房間名稱，不是密碼；參與者仍需各自的觀看及 SyncPlay 權限。現有實作包含登入世代檢查、伺服器時間估計、500 ms 漂移門檻、最多 30 秒的單次修正，以及斷線後明確重連。未修改來源的七組 SyncPlay 基準測試為 **105 通過**；以下問題需要額外案例才能重現，既有通過數不代表不存在競態。

## 發現與修正

| 重現條件 | 修正前 | 修正後及回歸測試 |
|---|---|---|
| 待處理 Unpause 同時遇到時間 API 失敗或無效時間樣本 | `synchronizeClock` 收尾再次 drain，立刻產生第二次時間請求，可能持續快速重試 | 先安裝既有 60 秒輪詢，待處理指令尊重排程；測試確認 59.999 秒內不重試、到期一次恢復，以及斷線後明確重連取消舊排程 |
| 遠端 Unpause 已進入真實 adapter，仍等待播放器解除 buffering，此時斷線／GroupLeft／LibraryAccessDenied／清空佇列 | controller 只撤銷自己的 timer；底層 ready 後舊指令仍可能呼叫播放 | 所有播放世代失效統一撤銷 adapter 待處理工作；四種失效路徑解除 ready 後都沒有過期播放或 Ready 請求 |
| New 確認逾時、原始 REST 請求尚未完成，重連得到空列表 | 空列表被當作確定沒有房間，可回到 idle 並再次 New | 先等待原始會員請求；未收斂或結果不明時保持 unknown。已確認的唯一正向房間仍能重新加入，重連不會自動 New |

上述三項問題均先保存失敗測試，再以同一回歸案例驗證修正。時間重試測試還使用最終測試檔對原始 controller bytes 重跑，確認不是測試設定造成的假失敗。

## 檢查矩陣

| 項目 | 程式及自動化檢查 |
|---|---|
| 建房／六位碼 | 精確六位 ASCII 數字、前導零、可見碰撞、零或多筆精確符合、大小寫及前綴相似名稱；不任選房間 |
| 權限 | 建立及加入／僅加入／無權限；開啟視窗以目前帳號刷新權限；401、未知權限及 A→B→A 過期結果；觀看權限仍交由伺服器判定 |
| 播放／暫停／跳轉 | 不同本機時鐘、伺服器 deadline、暫停時精確跳轉、較新指令撤銷舊工作、重複封包、手動控制與底層 echo 隔離、固定 1× |
| 緩衝 | 3000 ms 持續 waiting 才回報 Buffer；Ready 等實際底層就緒；Buffer／Ready 序列化、佇列及登入世代隔離、不盲重試 POST |
| 斷線重連 | 撤銷排程及執行中的播放工作；關閉舊 socket／heartbeat；先收斂原始 New／Join，再重新確認精確群組 |
| 帳號／來源切換 | 帳號、憑證、來源、session 世代失效後，舊 HTTP、WebSocket、載入與 Ready 不得影響新身分 |

建立前的列表檢查不是伺服器端原子預約。兩位建立者同時選中相同房碼仍可能產生重名；加入端會拒絕多筆符合，房碼不提供私密房間或密碼保護。

## 同步誤差診斷

房間視窗新增預設收合的本機診斷。資料只含數值：扣除伺服器處理時間的網路往返估計、伺服器減本機的時間差、所選最佳時間樣本年齡、校正前播放誤差、誤差樣本年齡、最近要求的校正量及成功校正次數。沒有有效樣本時顯示未知，不能顯示成零誤差。

診斷使用同一筆時間樣本及同一個讀取時間，避免到期邊界組合出不一致數值。測試覆蓋最低延遲樣本、有效零值、兩分鐘到期邊界與後備樣本、時鐘倒退、正負誤差、500 ms 門檻及 30 秒校正上限。校正尚未完成、失敗或中途失效時，不增加成功計數；換片、斷線或登入切換清除對應資料。

診斷是檢查時快照，不是持續計時或朋友裝置間的實測誤差。測試也直接檢查 `states` 串流最後發出的快照，確保收到 Pause 後 UI 不會保留舊誤差；另覆蓋收合、未知樣本與窄畫面兩倍文字。
