# JMS 掌機與輸入第一增量（本機開發）

來源基線為 ROGPC 既有 JMS、`18c54e16`，版本仍為 `0.11.1-jms.45+47`。本輪在隔離快照開發並驗證，再精確套用審查過的檔案。沒有發布、安裝或覆蓋現用 App，也沒有推送或建立遠端儲存庫。

## 已實作

- 共用 Flutter 焦點操作：方向導航、單次確認、按鍵長按／放開配對、返回後恢復仍存在的原控制項，焦點框與 Material 按鈕焦點邊框；焦點捲動可上下揭露控制項，尊重減少動畫偏好。
- Android 主 Activity 將左搖桿與方向帽轉為 DPAD 事件，含各軸 deadzone、方向穩定、重複節流與失焦／暫停／移除裝置釋放。沿用原有 Flutter 輸入路徑，不映射滑鼠。
- 真正控制器輸入與一般鍵盤分開辨識。普通鍵盤保留播放器既有快轉／音量快捷鍵；Linux Steam Input 若輸出鍵盤事件，可明確用 `--handheld` 啟動共用 UI。此旗標不儲存偏好、不更改系統設定，也不開啟 TV 模式。
- 掌機橫向邏輯視窗採單欄與較緊湊封面；播放器隱藏控制排除焦點，手把操作時維持控制列可見，隱藏時先喚出，返回先隱藏再退出。較窄視窗的播放控制與音量／選單分成兩列。
- Windows 滾輪沿用既有未提交的平滑控制器，只調整新行程起始斜率（3 → 1.5），保留 160ms 行程、連續目標累積、立即反向、觸控板原生路徑及焦點捲動中斷。
- 原生 runtime 發現播放選單覆蓋滑鼠區域時會隱藏手把控制列、返回焦點重設；已修正並以實際選單回歸。播放選單長片名加上寬度約束、兩行省略及完整語意／Tooltip。
- 設定入口改用「一般」，移除一般／個人資料／播放器／關於四個重複副文；保留必要幫助、管理與隱私同意。詳見 [UI 首批審視](JMS_UI_REVIEW_20261024.md)。

Discord 的選片／明確詳情／觀看／暫停／退出清理已存在於原先未提交的工作，本輪保留實作並增加本機模擬回歸；沒有啟用狀態分享或對外廣播。

## 隔離原生 runtime 結果

使用者另行核可唯一命名的 `codex_jms_input_probe_20261024.exe` 後，經相同 CUA 路徑啟動，核對完整執行檔路徑、boot 與視窗身分才操作。修正後最後建置 exit 0；原生實測已完成，測試視窗已關閉。沒有操作或關閉現用安裝版 JMS，沒有載入主 App、登入或保存偏好。

- Windows 原生 wheel 100 delta 分多幀到達目標；快速追加保留累積距離，反向後下一個取樣已下降。量測證明位移連續，沒有把 Debug／同步日誌當成幀率或實際手感基準。
- 合成媒體卡片可方向導航與上下自動捲動；確認開詳情、返回恢復原卡片。長對話框可方向捲動、只選取一次並返回原入口。
- 真正 `DesktopControls` 可從播放鍵移到快轉與更多；手把方向不直接快轉。播放選單關閉保留更多焦點；隱藏控制先喚回，再返回詳情。837×494 client 下兩列控制可用，選單可捲到末端品質選項。
- 原生觀察的 client 為 1264×761、1264×681、837×494（Windows 外框請求 1280×800、1280×720、853×533），不是 Deck 實體解析度。另有 Android／Linux 六組精確邏輯尺寸 widget 驗證。
- 切回一般鍵盤模式後，右鍵仍直接執行 mock 快轉。鍵盤空白鍵在此輪 native trace 未產生可確認的暫停事件，僅有自動化回歸證據，不列為原生驗收。
